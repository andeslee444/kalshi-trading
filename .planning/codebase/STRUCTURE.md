## Directory Purposes

**src/kalshi/:**
- Purpose: All production bot code and shared modules
- Contains: Bot scripts (*.py) and shared libraries (kalshi_auth, probability, capital_allocator, ticker_utils, hdd_parser, polymarket_client)
- Key files: `kalshi_auth.py` (400+ lines), `probability.py` (450+ lines), `capital_allocator.py` (300+ lines), individual bots (15-60KB each)

**scripts/:**
- Purpose: Operational tools, analysis, and process management
- Contains: Supervisor, dashboard, audit/backtest scripts, data reconciliation
- Key files: `supervisor.py` (process manager), `dashboard.py` (web UI), `audit.py` (system audit), `backtest.py` (performance evaluation)

**config/:**
- Purpose: Static configuration and API keys
- Contains: Bot settings (maxTradeAmount, cities, scan intervals), calibration parameters, RSA private keys
- Key files: `kalshi-config.json` (weather), `kalshi-monitor-config.json` (source monitor), `bots-config.json` (other bots), `calibration.json` (sigma tuning)

**data/:**
- Purpose: Runtime state and observability (gitignored, synced to S3)
- Contains: Trade logs, decision logs, health monitoring, circuit breaker state, market cache
- Key files: `kalshi-trades.json` (golden record), `*-trades.json` (per-bot logs), `*-decisions.json` (audit trail), `health-state.json` (heartbeats)

**tests/:**
- Purpose: Unit and integration tests (22 test files, ~2000 test cases)
- Contains: Tests for probability models, trade managers, allocators, bots, optimization
- Key files: `conftest.py` (path setup), `test_probability.py`, `test_trade_manager.py`, `test_allocator.py`

**archive/:**
- Purpose: Historical code (not executed)
- Contains: Numbered bot iterations (cycle3-cycle21.py), predecessor scripts
- Use: Reference only — do not import or execute

## Key File Locations

**Entry Points:**
- `src/kalshi/weather-bot.py` — Weather market trading (npm run weather)
- `src/kalshi/entertainment-bot.py` — Album sales trading (npm run entertainment)
- `src/kalshi/source-monitor.py` — Information arbitrage (npm run monitor)
- `src/kalshi/crypto-bot.py` — BTC/ETH trading (npm run crypto)
- `src/kalshi/economics-bot.py` — Nowcast trading (npm run economics)
- `src/kalshi/beatrelease-scanner.py` — Music release arbitrage (npm run daemon, or direct)
- `src/kalshi/strategy-trader.py` — Longshot + settlement arb (npm run strategy)
- `src/kalshi/position-monitor.py` — Exit management (npm run positions)
- `scripts/supervisor.py` — Process manager (npm run supervisor)
- `scripts/dashboard.py` — Web UI (npm run dashboard)

**Configuration:**
- `config/kalshi-config.json` — Weather bot: cities, maxTradeAmount, edgeThreshold, ensemble settings

**Core Logic:**
- `src/kalshi/kalshi_auth.py` — KalshiClient (API), TradeManager (order placement), CircuitBreaker, auth infrastructure
- `src/kalshi/probability.py` — Probability models (weather, info-arb, nws, econ, crypto), Kelly sizing

**Testing:**

## Naming Conventions

**Files:**
- Bots: kebab-case: `weather-bot.py`, `entertainment-bot.py`, `source-monitor.py`
- Shared modules: snake_case: `kalshi_auth.py`, `probability.py`, `capital_allocator.py`
- Scripts: kebab-case: `daily-report.py`, `reconcile-trades.py`, `s3-sync.sh`
- Tests: `test_` prefix: `test_probability.py`, `test_weather.py`

**Directories:**
- Python packages: lowercase: `kalshi`, `src`, `tests`
- Data directories: lowercase: `data`, `logs`, `pids`, `config`
- Archive: `archive/` (historical code, not imported)

**Functions & Classes:**
- Classes: PascalCase: `KalshiClient`, `TradeManager`, `CircuitBreaker`, `PortfolioAllocator`
- Functions: snake_case: `setup_logging()`, `weather_probability()`, `half_kelly()`
- Private functions: leading underscore: `_norm_cdf()`, `_load_calibration()`

**Variables:**
- Constants: UPPER_CASE: `DEMO_BASE_URL`, `MAX_RETRIES`, `MARKET_CACHE_TTL`
- Module-level config: lowercase: `config`, `client`, `trade_manager`

**Trade Log & State Files:**
- Format: JSON (human-readable, atomically written)
- Naming: `{context}-{entity}.json` where context ∈ {kalshi, data} and entity ∈ {trades, decisions, state}
- Examples: `kalshi-trades.json`, `kalshi-crypto-trades.json`, `kalshi-*-decisions.json`

## Where to Add New Code

**New Trading Bot:**
- Implementation: Create `src/kalshi/{name}-bot.py` following the pattern:
  1. Import from kalshi_auth, probability, capital_allocator, ticker_utils as needed
  2. Call `setup_logging()`, `setup_unbuffered()`, `setup_signal_handlers()`
  3. Load config from `config/` (create if needed)
  4. Instantiate `KalshiClient`, `PortfolioAllocator`, `TradeManager`, `HealthCheckMonitor`, `OrderMonitor`
  5. Implement main loop: fetch data → calculate probability → request budget → size position → place order
  6. Write trade records via `TradeManager.place_order()`
- Test: Create `tests/test_{name}.py` with pytest fixtures, mocking kalshi_auth
- NPM script: Add to `package.json` scripts section
- Config: Add settings to `config/bots-config.json` (maxTradeAmount, maxDailyTrades, maxDailyLoss, etc.)
- Monitoring: Add entry to `BOT_PRIORITY` in `src/kalshi/capital_allocator.py`

**New Probability Model:**
- Implementation: Add function to `src/kalshi/probability.py`
- Pattern: `def {market_type}_probability(observed, threshold, ...): return cdf_value (0-1)`
- Use: `_norm_cdf()` or `_student_t_cdf()` for standard CDFs; no scipy dependency
- Calibration: Add parameters to `config/calibration.json` if tunable; lazy-load in function via `_load_calibration()`
- Test: Add to `tests/test_probability.py`

**New Shared Utility:**
- If it's auth/API: Add to `src/kalshi/kalshi_auth.py` (already 1000+ lines, but centralized)
- If it's ticker parsing: Add to `src/kalshi/ticker_utils.py`
- If it's data parsing: Create new module in `src/kalshi/{domain}_parser.py` (e.g., `hdd_parser.py`)
- Test: Create `tests/test_{module}.py`

**New Operational Script:**
- Implementation: Create `scripts/{purpose}.py` (e.g., `daily-liquidation.py`)
- Pattern: Standalone script; import from `src/kalshi/` as needed
- Register: Add npm script to `package.json` if it's user-facing
- Logging: Use `setup_logging("{script_name}")` from kalshi_auth

**New Data Analysis:**
- Implementation: Create script in `scripts/` or one-shot in bot itself
- Output: Write results to `data/` (e.g., `data/analysis-results.json`)
- Consumption: Dashboard or audit script reads and displays

## Special Directories

**archive/:**
- Purpose: Superseded code (historical reference)
- Generated: No (hand-maintained)
- Committed: Yes (gitignored in some repos, kept here for reference)
- Use: Read-only; do not import or run in production

**config/keys/:**
- Purpose: RSA private keys (gitignored)
- Generated: No (must be created manually or via key management system)
- Committed: No (.gitignore excludes)
- Files: `kalshi-demo.pem`, `kalshi-live.pem` (required by KalshiClient)

**data/logs/:**
- Purpose: Rotating log files (5MB, 3 backups per bot)
- Generated: Yes (auto-created by setup_logging())
- Committed: No (gitignored)
- Rotation: Handled by Python's RotatingFileHandler

**data/pids/:**
- Purpose: Process ID files for supervisor (tracking running bots)
- Generated: Yes (by supervisor.py)
- Committed: No (gitignored)
- Content: One file per bot with PID, uptime, restart count

**data/kalshi-source-snapshots/:**
- Purpose: Snapshots of external data (for audit trail)
- Generated: Yes (by source-monitor.py on each scan)
- Committed: No (gitignored)
- Cleanup: Auto-deletes snapshots >7 days old

**data/kalshi-source-snapshots/hdd/:**
- Purpose: HITS Daily Double snapshots
- Generated: Yes (by hdd-scraper.py)
- Format: JSON (Sanity CMS response) or HTML
